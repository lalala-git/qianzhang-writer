# 网文作者痛点与功能边界

千章面向持续连载的作者，把写作、规划、章节自查和本地保存放在同一个工作区。这份说明整理功能对应的需求；安装方式和完整使用入口见 [README](../README.md)。

## 日常写作与连续更新

| 常见需求 | 千章提供的功能 | 使用边界 |
| --- | --- | --- |
| 看清每日进度，保持连更 | 每日字数目标、连更日历、写作统计、字数与章数里程碑 | 今日字数按写作页实际输入统计，导入内容不计入今日产量 |
| 判断存稿能撑多久，安排更新 | 存稿统计、每天更新章数、计划发布日期与到期提醒 | 发布状态由作者维护；计划日期用于本地提醒，不会自动上传到小说平台 |
| 卡文时找到下一步 | 每章细纲、章节模板、前情与伏笔提示、可选 AI 卡文助手和陪写 | 本地提示来自规则；AI 建议需要配置模型，采用前由作者判断 |
| 减少写作时的打断 | 简化导航、可折叠检查面板、提醒频率设置、专注模式 | 专注与提醒是写作辅助，作者可以调整使用方式 |
| 保存零散灵感和查到的资料 | 素材墙、标签、关联章节或人物、写作页插入素材 | 素材由作者整理，工具不会替作者核实资料真实性 |

## 长篇结构、人物与设定

| 常见需求 | 千章提供的功能 | 使用边界 |
| --- | --- | --- |
| 章节多了以后难以规划 | 分卷目录、每章细纲、故事内时间、情节分支 | 当前围绕卷与章组织内容，不等同完整的多级场景编排系统 |
| 埋下的伏笔忘记回收 | 伏笔登记、计划回收章节、到期或逾期提示 | 提醒依据登记信息；是否已经在正文中妥善回收，需要作者确认 |
| 人物称呼多，关系和状态难以记住 | 人物与设定卡、别名及称呼范围、关系图、按章记录状态 | 自动识别可能漏报或误报，卡片内容仍由作者维护 |
| 人名写成异体字、全角字或多空格形式 | 疑似错名与别名建议、按章预览、全书统一和撤销 | 一名多人等歧义需要人工处理，不应直接批量替换 |
| 人物受伤、死亡或成长后又出现矛盾 | 状态变化、正文死亡句提示、人物出场与成长分析 | 本地规则无法完整理解回忆、比喻、假设和叙事意图；提示不是事实判定 |
| 希望从角色视角检查设定 | 可选角色聊天，参考人物档案、关系、规则和最近剧情 | 模型可能补充或误解内容，对话不能自动成为正典 |

## 章节自查与改稿

| 常见需求 | 千章提供的功能 | 使用边界 |
| --- | --- | --- |
| 写完后检查错字、重复和排版 | 词表与规则检查、疑似错名、敏感词、口头禅、长句、长段、标点及占位符定位 | 词表和阈值只能提供线索，不保证找全问题或通过平台审核 |
| 看清开篇、章末和全书节奏 | 黄金三章、章末钩子、对白比例、人物出场、节奏与文风统计 | 数字和提示用于辅助自查，不代表作品质量、读者反应或签约结果 |
| 改稿时保留可回退的版本 | 历史稿、情节分支、差异比较、替换前快照、搜索替换与撤销 | 只能恢复已经保存的记录；浏览器清理和设备故障仍需要异机备份应对 |
| 统一不同平台的排版 | 平台格式预设、发布前自查、一键复制、章节或全书导出 | 作者仍需自行到目标平台发布，并按平台当前要求复核 |
| 整理读者建议和后台数字 | 粘贴或导入评论与章节数据，按规则分类并展示走势 | 不会自动登录平台或抓取后台；数据含义与分析结论需作者核实 |

## 数据保存与可选 AI

- 源码服务把作品保存在本机的 `data/projects/`，并提供本地备份和回收站。浏览器还会尝试保留副本，实际保存状态应以界面提示为准。
- 本地备份和浏览器副本仍属于本机数据。迁移设备或防范设备损坏时，需要导出并在另一位置保留副本。
- 不配置 AI 也能使用本地写作、规划和规则检查功能。
- AI 密钥由本地服务加密保存在数据目录里，不进浏览器存储；导出备份默认不含密钥。陪写默认关闭，打开时会说明会发送什么，开着时写作页顶部一直有「陪写开」指示，一点就关。
- 使用远程 AI 时，浏览器会向作者选择的接口发送该功能所需的正文、人物设定、世界规则、最近章节或对话上下文。接口需要支持浏览器跨域访问，使用额度和费用由所选服务商决定。
- AI 结果需要作者审阅；把草稿放入正文、采纳设定或标记发布，仍是作者的决定。

## 当前范围

千章侧重本机连载写作。当前没有多设备自动同步，也不提供小说平台自动发布。本地检查采用词表、统计和启发式规则，无法替代作者对语义、设定一致性和平台要求的判断。

功能入口与配置方法以 [README](../README.md) 为准；具体修改见 [更新记录](../CHANGELOG.md)。
